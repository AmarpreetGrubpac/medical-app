# Server fixes required for GrubPac Medical

22 October 2026. Handoff for the server team; app code is the only repository available here. Reproductions used isolated preproduction boxes. Do not run mutations against live medical contents. Use the supplied test accounts through secure credentials sharing, not this document.

API base: `https://preprod.43.204.34.10.nip.io/api/v1/`. `{role}` below is `owner` or `driver`; use each account's own token. Evidence: [sanitized HTTP calls](../reports/preprod-2026-10-22/api-results.json), keyed by `case`.

| Priority / audit ID | Current failure | Required server behavior and acceptance checks |
|---|---|---|
| P0 F03 | `PATCH medical-mobile/{role}/boxes/{id}/settings` with `zone_1_temp` changes the **sensor measurement**; target stays 4. `zone_1_target_temp` is rejected with 400. Detail settings also omit/null the real target while simulator health exposes it. | Accept explicit `zone_1_target_temp` / `zone_2_target_temp`, return desired targets consistently in box detail/list/health, and preserve measured `zone_1_temp` / `zone_2_temp`. App now sends target fields only; these requests remain blocked until service support. Set target 8, assert measurement unchanged immediately, target 8 across reload, and physical convergence only through sensor telemetry. Test both roles/zones. |
| P0 F04 | Temperature 999 returns 200 and reads back as 999 (`owner.range.verify_999`). | Enforce agreed device and medical operating limits server-side, finite numeric types and explicit validation errors. Values outside bounds, invalid types and unauthorized changes must not alter state. Publish supported bounds/capabilities; app's existing -20…70 slider limits are not a medical policy. |
| P0 F06 | `POST medical-mobile/driver/boxes/{id}/otp-lock` returns 404. | Publish and implement OTP request, recipient selection, verify and resend routes/payloads. Return masked recipient, challenge identifier, expiry/cooldown and rate-limit errors. Lock state must change only after valid authorized verification. Test wrong/expired/reused/cross-box codes, retry, duplicate requests and actual lock readback. App now reports failure instead of premature success; the complete OTP screen awaits this contract. |
| P1 F01 | `POST medical-mobile/auth/refresh` returns 404 for both roles. | Implement documented refresh with `refresh_token`; return new `data.auth_token` and refresh token as applicable. Define rotation, expiry/reuse and rejection status. Verify expiry during a shift, concurrent 401s, one refresh and one retry; invalid refresh ends the session. |
| Release environment F02 | Strict TLS certificate verification fails on preproduction. Debug-only bypass is not release readiness. | Install trusted certificate/full chain covering this hostname. Prove standard TLS from Android/iOS release builds and strict HTTPS clients. Do not solve by shipping a certificate-verification bypass. |
| P1 F07 | Settings PATCH with `zone_1_status`/`zone_2_status` returns 400 “At least one setting field is required.” | Accept and persist supported zone status fields; enforce device capabilities and permissions. Readback and subsequent detail/health agree. App now sends requests and rolls back on rejection instead of pretending local persistence. |
| P1 F08 | Per-box `PATCH .../boxes/{id}/lock` with `{action: unlock}` acknowledges but stays locked. Working owner routes are `PATCH .../grublock/emergency_unlock` and `.../grublock/lock`, `{ids: [...]}`. | Fix or formally retire/document the per-box endpoint. Preserve owner/driver permissions and return command/physical-state semantics. App removed this unreliable fallback and verifies lock state before success. Test command rejection, delayed acknowledgment and readback mismatch. |
| P1 F09 | GPS flag can be true with null or placeholder 0,0 coordinates; no trustworthy sensor fix timestamp was supplied in audited detail data. | Provide selected-box coordinates with validity/fix timestamp and stale/offline semantics. Define coordinate source; expose timestamped GPS telemetry to mobile roles. Test no fix, stale fix, permission boundaries and moving box. App no longer substitutes phone/default-city coordinates or claims “just now” sensor freshness. |
| P1 F11/F14 | Facility emergency contact/action contract is absent from available mobile data; FAQs/categories are empty. | Supply real per-facility contact and authorized emergency alert endpoint with selected-box context, acknowledgment, duplicate protection and failures. Seed medical FAQs/categories. Agree delivery recipients and escalation semantics before end-to-end tests. App removed the example dialer number; deployment may supply `FACILITY_PHONE` until an API contact contract exists. |
| Contract F05 | Notifications use `body`, `severity`, `box_id`; app formerly expected description/type/name. | App mapping is repaired. Keep the schema stable and document supported severity/category values, pagination, timestamps and box metadata/identity. Seed multi-box warning/error events to validate paging/filtering and cross-organization isolation. |
| Policy F12 | Logout returns 200; previously issued access token still accesses profile. | Decide/document token expiry and revocation policy. If logout must revoke immediately, implement it; otherwise document access-token TTL and refresh revocation. This observation alone is not classified as a security breach. |
| Contract F16 | Malformed email resolves as account-not-found; some invalid limits return 200. | Agree email normalization and pagination default/min/max behavior; provide consistent validation and bounded queries. Validate semantics, not status codes alone. |

After implementation, rerun the [acceptance matrix](../reports/preprod-2026-10-22/scenario-matrix.csv) and [operational journeys](../reports/preprod-2026-10-22/REAL_WORLD_USE_CASES.md). Snapshot settings, readings, locks, pairing and connection first; compare and restore after every mutable run. API acknowledgment alone is insufficient to pass physical control.

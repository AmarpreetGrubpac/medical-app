# Findings & Decisions

## Requirements
- Create a virtual box simulator using React to mimic physical box behaviors (e.g. temperatures, battery levels, connection status, lock/unlock state, alerts).
- Connect commands sent from the Flutter app/server to the React simulator (e.g., locking/unlocking, modifying settings).
- Propagate status changes and events triggered on the simulator (e.g. low battery alert, temperature modifications) back to the server, which then reflects in the Flutter app.
- Provide a robust architecture for the simulator.
- Use a heartbeat signal from the simulator to the server to report status, or from the Flutter app to the server to get box status.
- Review and suggest changes for the planned API specifications in `Driver_app_bugSheet - virtualBox-api_req.md`.
- Generate a QR code displaying `{"box_display_id": "display_id"}` format to allow pairing the box in the driver app.

## Research Findings
- **API Spec Analysis (`Driver_app_bugSheet - virtualBox-api_req.md`)**:
  - `PATCH /api/v1/simulator/boxes/{box_id}/state`: Payload includes comprehensive properties (`connection_status`, battery levels, zone temps, GPS, etc.). Missing fields like `battery_level`, `latitude`, `longitude`, `advert_screen`, `ioniser`, `light_status`, `gyrosensor`, `turn_signals` are marked as `(MISSING)`.
  - `PATCH /api/v1/simulator/boxes/{box_id}/lock` & `PATCH /api/v1/simulator/boxes/{box_id}/unlock`: Endpoints for locking/unlocking the box.
  - `POST /api/v1/simulator/boxes/{box_id}/events/trigger-alert`: Dispatches alerts (e.g. Low Battery) with fields `box_id`, `category`, `type`, `title`, `description`.
  - `GET /api/v1/simulator/boxes/{box_id}/health`: Returns health status (e.g. on/off).
  - `PATCH /api/v1/simulator/boxes/{box_id}/settings`: Sent by backend when driver changes settings in Flutter app (e.g. ioniser, dual_zone, etc.).
  - `POST /api/v1/simulator/boxes/{box_id}/connection`: Sent by backend when a driver links to the box. Payload contains `driver_id` and `restaurant_id`.
  - `DELETE /api/v1/simulator/boxes/{box_id}/connection`: Unlinks the driver.

- **FVM/Flutter Environment & Scan Box Controller**:
  - The repo contains a Flutter app (uses `.fvmrc`, has `lib`, `android`, `ios` directories).
  - Open Dart file: `lib/screens/box_details/controller/box_details_controller.dart`. This indicates the Flutter app has a controller for displaying box details.
  - Scan Box controller in [scan_box_controller.dart](file:///Users/robin/Desktop/driver_app-zabee_working/lib/screens/scan_box/controller/scan_box_controller.dart) expects scanned QR code value in JSON string format: `{"box_display_id": "display_id"}`.

## Technical Decisions
| Decision | Rationale |
|----------|-----------|
| HTTP Heartbeat Broker | Simplest to implement, stateless, self-healing, low overhead. |
| Email Delivery for OTP | Simulating actual production flow where OTP is delivered outside the box display. |
| JSON QR Format | QR code generated by the simulator will output `{"box_display_id": "display_id"}` to be compatible with the driver app scanner. |
